# 视频导入：移除 base64 往返

## 实现

视频提取结果通过内部 `sourcePath` 传入帧导入模块，每次只读取一帧、校验 PNG 头并写入暂存目录。导入过程不再创建整个视频的 base64 列表和解码后的 Buffer 数组。

已有 data URL 输入继续受支持；同时提供 inline data 与 sourcePath 时，普通导入仍优先使用 inline data，in_place 导入仍使用源路径。视频依旧不允许 in_place。临时提取目录在导入、同步和验证结束后由原有 finally 清理；所有帧准备完成后才执行原有提交与回滚流程。

## 功能验证

新增 6 项测试，完整检查共 350 项通过：

- 视频路径与外部 base64 输入产生相同的逐帧 SHA-256、动画清单、调参数据及 Godot 输出；样本覆盖不同帧内容、半透明像素、FPS 和截取范围。
- 视频入口没有 PNG base64 编码步骤。
- 缺失中间帧、损坏中间帧、提取失败均保留已有 PNG、清单与调参数据，并清理临时目录。
- 清单提交失败恢复原有帧及数据。

已有测试继续覆盖成功替换、in_place、抠图、同步和公开工具探针。等价性样本使用可控的提取替身；真实 FFmpeg 提取代码没有改动。

## 性能对比

同一台 Apple M3 / macOS arm64 / Node v22.12.0，修改前后分别执行 `node tools/benchmark_mcp.js`。保留的原始记录：`video-import-before-2026-09-05.json` 与 `video-import-after-2026-09-05.json`。

| 帧数 | 修改前导入 | 修改后导入 | 耗时减少 | 修改前峰值 RSS | 修改后峰值 RSS | 峰值减少 |
| ---- | ---------- | ---------- | -------- | -------------- | -------------- | -------- |
| 100  | 826 ms     | 755 ms     | 8.5%     | 316 MiB        | 179 MiB        | 43.4%    |
| 500  | 3935 ms    | 3707 ms    | 5.8%     | 539 MiB        | 316 MiB        | 41.3%    |

工作负载是相同的 512×512 合成 PNG，每张约 332 KiB；每种规模单独启动进程。提取替身把预生成 PNG 复制到临时目录，所以导入耗时包含复制，不含真实视频解码。峰值 RSS 包含整个子进程的素材生成、服务加载、导入和摘要读取。每个规模的导入只测一次，结果用于说明本机样本收益，不是稳定吞吐保证。

此次主要减少同时持有的编码副本与解码字节。PNG 解码、碰撞框估计、观察哈希和 STDIO 排队仍有成本；ping 仍会等待长任务。下一步若继续优化，应测这些阶段的占比，保持写入有序性和快照新鲜度校验。
